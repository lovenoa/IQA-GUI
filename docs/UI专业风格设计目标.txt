# UI 实施任务：专业桌面工具视觉系统

请根据本规范，为当前项目建立并实现完整、统一的桌面 UI 设计系统。

## 设计目标

专业工具型、紧凑信息密度、轻微圆角，同时支持深色和浅色主题。整体应具有成熟专业软件的质感，避免常见 AI 生成网页模板的视觉特征。

## 实施要求

1. 先检查现有项目的技术栈、窗口结构、组件库、功能流程与实际约束，再确定最合适的实现方案。不要为了设计偏好无理由重写技术架构。
2. 建立统一的颜色、字体、间距、圆角、控件尺寸与状态变量，避免样式散落、重复定义和主题不一致。
3. 根据实际工作流程安排布局，让核心工作区优先获得空间。不要机械地使用三栏布局，也不要把每个功能区都包装成卡片。
4. 实现完整的深浅主题，包括面板、表格、输入框、弹窗、状态提示及其他可控组件。
5. 统一按钮层级、控件高度、图标风格、对齐规则、悬停与焦点反馈。
6. 兼顾高信息密度与可读性，避免极小字号、无意义留白、过度装饰和低对比度文字。
7. 处理窗口缩放、长文本、空数据、加载、失败、取消和其他实际状态。
8. 不得用静态样例或装饰性组件冒充尚未实现的真实功能。不要为了截图好看而牺牲交互和数据准确性。

## 工作方式

请结合项目情况自主判断，不必机械遵循每项建议。若现有架构存在明显限制，优先选择成本合理、维护性良好的方案，并说明重要取舍。

完成实现后，实际运行项目并检查关键界面。至少覆盖深浅主题、不同窗口尺寸、主要操作、异常状态和长内容。能够使用截图时，应检查真实渲染效果，而不只是检查代码或 CSS。

## 交付要求

请说明：
- 实际采用的设计方案及关键取舍；
- 主要修改的文件与组件；
- 深浅主题和设计变量的组织方式；
- 实际运行与验收的结果；
- 尚未解决的视觉问题或功能限制。

最终目标是形成一套视觉统一、信息清晰、操作高效、能够持续维护的专业桌面 UI，而不是仅完成一张美观的静态页面。
